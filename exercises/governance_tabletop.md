# Governance Tabletop — Control Exceptions and Evidence Quality

## Scenario

A fictional security steering committee receives a quarterly assurance report showing several overdue evidence reviews and open exceptions across identity, resilience, data protection, and third-party controls.

The exercise focuses on ownership, evidence quality, exception governance, risk communication, and executive decision-making.

## Objectives

- distinguish stale evidence from ineffective controls;
- identify accountable control owners;
- prioritize exception review;
- practice concise executive reporting;
- document risk acceptance or remediation decisions;
- define follow-up evidence requirements.

## Starting information

Use `datasets/sample_governance_controls.csv` and `datasets/sample_control_evidence.csv` as fictional inputs.

## Discussion injects

1. A critical resilience control has an open exception and overdue evidence.
2. The control owner believes the underlying control still operates effectively.
3. An executive asks whether the exception can be accepted until the next quarter.
4. A supplier-related control has current evidence but a newly identified dependency concern.
5. Two reports use different severity labels for similar issues.

## Questions

- What evidence would support a temporary risk-acceptance decision?
- Who should approve an exception for a critical control?
- How should conflicting severity labels be normalized?
- What information belongs in an executive summary versus an analyst appendix?
- When does evidence age become a governance issue even if no failure is known?
- Which decisions need explicit expiry dates and reassessment triggers?

## Outputs

Produce a fictional exception register update, executive summary, decision record, evidence-request list, and follow-up schedule.

## Safety boundary

This exercise uses fictional governance records only and does not require interaction with real systems, accounts, suppliers, or production controls.
