# Contributing

Thank you for helping improve the companion resources for **The Journey of Ethical Hacking**.

## Good contributions

Contributions should improve defensive education, documentation, accessibility, synthetic/offline labs, safe tooling, tests, templates, learning aids, or error corrections.

## Not accepted

Do not submit exploit chains, credential theft, malware, persistence, stealth/evasion, destructive actions, unauthorized scanning workflows, instructions for bypassing security controls, or sensitive real-world target data.

## Contribution checklist

- Keep examples fictional, local, isolated, or explicitly authorized.
- Prefer synthetic datasets and read-only evidence review.
- Remove secrets, credentials, tokens, personal data, and third-party target information.
- Explain the defensive learning objective.
- Add tests or validation notes when changing code.
- Keep documentation clear enough for beginners to understand the safety boundary.
